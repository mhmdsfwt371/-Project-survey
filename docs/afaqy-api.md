## ١. حالة التوثيق — ما تم التحقق منه فعليًا

| المصدر | الرابط | النتيجة |
|---|---|---|
| نظام أفاقي للعملاء | `myafaqy.com` | تطبيق صفحة واحدة، مقفول بتسجيل دخول، يرفض الفحص الآلي. **لا توثيق عام لواجهته** |
| قاعدة المعرفة | `docs.afaqy.pro` | تشرح استخدام المنتجات (AVL / Route / X-Rent / SenseWare) — **ليست مرجع مطورين** |
| شبكة بوستمان العامة | `postman.com` | **لا توجد** مجموعة رسمية لأفاقي. المجموعة المسماة «Afaqy Integration API» تخص جهة أخرى (مستقبِل بيانات لمركز طبي) — غير ذات صلة |
| بيئة الاختبار | `web.avl.test.afaqy.pro` | صفحة دخول فقط |

**الخلاصة:** كل واجهة سنستخدمها لا بد أن تُلتقط من داخل النظام أو تُطلب من فريق التطوير الداخلي.

## ٢. التقاط أي واجهة في دقيقتين (بدون سؤال أحد)

1. افتح النظام على الكمبيوتر وسجّل الدخول.
2. اذهب للصفحة التي تعرض البيانات المطلوبة (مثلًا: قائمة الأجهزة).
3. اضغط `F12` ← تبويب **Network** ← فلتر **Fetch/XHR**.
4. حدّث الصفحة (`Ctrl+R`). ستظهر الطلبات.
5. اضغط الطلب الذي يحمل البيانات، وسجّل منه:
   - **Request URL** (الرابط الكامل)
   - **Method** (GET / POST)
   - **Request Headers** — اسم ترويسة المصادقة فقط (مثل `Authorization` أو `X-API-Key`) — **لا تنسخ قيمة التوكن**
   - **Response** — انسخ **عنصرًا واحدًا** من المصفوفة لمعرفة أسماء الحقول

> ⚠️ **قاعدة أمنية ثابتة:** لا يُكتب أي توكن أو كلمة مرور في هذا الملف — المستودع عام.
> التوكن يوضع في: إعدادات المستودع ← Secrets and variables ← Actions ← Secrets.

## ٣. سجل الواجهات المكتشفة

> يُملأ تدريجيًا. القالب أدناه يُنسخ لكل واجهة جديدة.

### قالب

```
### اسم الواجهة
- الغرض:
- الرابط:
- الطريقة (GET/POST):
- المصادقة: (اسم الترويسة + نوعها: Bearer / API Key / Cookie)
- المعاملات:
- مسار المصفوفة في الرد: (مثال: data.items)
- الحقول المهمة:
- ملاحظات:
```

### (١) قائمة الأجهزة — قيد الانتظار
- الغرض: جلب الأجهزة (القارئات) لسجل العُهدة في تطبيق نُسُك
- الحالة: **لم تُلتقط بعد** — تُملأ بالخطوات في القسم ٢
- المطلوب منها: السيريال + الاسم/الموديل (اختياري: الحالة، الموقع، تاريخ الصرف)

## ٤. الربط بتطبيق نُسُك — جاهز ومنتظر البيانات فقط

**البوت:** `scripts/devices.mjs` + `.github/workflows/devices.yml`
يعمل كل ٦ ساعات وبتشغيل يدوي، ويكتب مباشرة في `settings/devices` بفايرستور.
إن لم تُضبط الأسرار يخرج بهدوء دون خطأ.

### الأسرار (Secrets) — قيم حساسة
| المفتاح | الوصف |
|---|---|
| `FIREBASE_SERVICE_ACCOUNT` | مضبوط مسبقًا (يستخدمه بوت النسخ الاحتياطي) |
| `DEVICES_API_URL` | رابط واجهة قائمة الأجهزة |
| `DEVICES_API_TOKEN` | التوكن — يُضاف يدويًا ولا يُشارك مع أحد |

### المتغيرات (Variables) — غير حساسة
| المفتاح | الافتراضي | الوصف |
|---|---|---|
| `DEVICES_AUTH_HEADER` | `Authorization` | اسم ترويسة المصادقة |
| `DEVICES_AUTH_PREFIX` | `Bearer` | البادئة، أو `none` لبدون بادئة |
| `DEVICES_JSON_PATH` | — | مسار المصفوفة في الرد، مثل `data.items` |
| `DEVICES_FIELD_SERIAL` | `serial` | اسم حقل السيريال |
| `DEVICES_FIELD_NAME` | `name` | اسم حقل الاسم/الموديل |
| `DEVICES_NAME_FILTER` | — | فلترة بالاسم قبل الاستيراد |

### الشكل الذي يكتبه البوت (وتقرأه واجهة نُسُك)
```json
{
  "list": [ { "s": "السيريال", "n": "الاسم أو الموديل" } ],
  "n": 0,
  "at": "YYYY-MM-DD HH:mm",
  "src": "api"
}
```

### البديل العامل اليوم
تصدير قائمة الأجهزة إلى إكسل أو CSV ← استيرادها من:
لوحة المتابعة ← **عُهدة الأجهزة** ← «ملف الأجهزة» (العمود الأول السيريال، الثاني الاسم).
